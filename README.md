# Slack bot backed by a Claude Managed Agent

A minimal, end-to-end example of connecting **Anthropic's Claude Managed Agents** to **Slack** using the [CopilotKit Channels SDK](https://www.copilotkit.ai/channels-guide.md) — with no infrastructure of your own.

> Slack thread in → Claude Managed Agent session out. CopilotKit owns the Slack plumbing, Anthropic owns the agent loop, this repo is just a ~200-line bridge between the two.

```
Slack ⇄ CopilotKit Intelligence (managed transport: events, tokens, outbound WS)
              ⇄ this service (channel handlers — runs anywhere, even a laptop)
                    ⇄ Anthropic Managed Agents API (sessions + SSE events)
```

**Who thinks vs. who moves bytes:** every reply is generated by a Claude Managed Agent — Anthropic runs the agent loop and a per-session sandbox (bash, files, web search). CopilotKit's hosted platform is transport only: it terminates Slack's webhooks, stores the Slack credentials, and delivers turns to this service over an *outbound* WebSocket, so you never expose a public endpoint.

## How it works

- Each Slack thread maps to one persistent Managed Agent **session** (mapping kept in `.data/sessions.json`), so conversation memory lives server-side and survives restarts.
- **Mention** the bot → the thread is subscribed and answered. Unmentioned follow-ups in a subscribed thread get replies. Fresh unmentioned conversations stay silent.
- Replies stream into Slack progressively as the agent produces them.
- Turns are capped (default 5 min); stale/terminated sessions are transparently replaced; failures post one short error message without leaking internals.

## Prerequisites

- Node.js 20+
- An **Anthropic** account with API access, and the [`ant` CLI](https://platform.claude.com/docs/en/api/sdks/cli) (`brew install anthropics/tap/ant`) — or an `ANTHROPIC_API_KEY`
- A **CopilotKit** account (free) for the hosted channel transport
- A **Slack workspace** where you can install apps

## Setup

### 1. Install

```bash
git clone https://github.com/cjavdev/managed-agents-channels-sdk.git
cd managed-agents-channels-sdk
npm install
cp .env.example .env
```

### 2. Provision the Claude Managed Agent

Authenticate with Anthropic (`ant auth login` — the SDK picks up the profile automatically, no key in `.env` needed), then create the environment and agent from the version-controlled YAML:

```bash
ENV_ID=$(ant beta:environments create < cma/environment.yaml --transform id -r)
AGENT_ID=$(ant beta:agents create < cma/agent.yaml --transform id -r)
echo "CMA_AGENT_ID=$AGENT_ID  CMA_ENVIRONMENT_ID=$ENV_ID"
```

Put both IDs in `.env`. These are **one-time** setup — agents are persistent, versioned resources. Don't re-create them per run; to change the prompt or tools later, edit `cma/agent.yaml` and apply it as a new version:

```bash
ant beta:agents update --agent-id $AGENT_ID --version <current> < cma/agent.yaml
```

### 3. Smoke-test the Anthropic side (no Slack needed)

```bash
npm run smoke
```

This creates a real session, sends one message, and streams the model's reply back. If this passes, the entire Anthropic half works — auth, session creation, event streaming, the drain loop.

### 4. Create a CopilotKit project

```bash
npx copilotkit@latest login
npx copilotkit@latest project select   # pick or create a hosted project
```

The CLI writes `INTELLIGENCE_API_KEY` into `.env` during setup.

### 5. Provision the Slack channel

```bash
npx copilotkit@latest channels add \
  --name cma-assistant \
  --display-name "CMA Assistant" \
  --adapter slack \
  --json
```

The command is a **resumable loop**: each run emits a JSON envelope with `status` (`completed` / `blocked`) and a `nextAction` telling you exactly what's missing and how to resume. Expect this sequence:

1. **`slack_app_not_created`** — the envelope includes a prefilled Slack manifest URL (also saved under `.copilotkit/artifacts/`). Open it, review, create the app.
2. **Reinstall to grant scopes.** Slack creates the app already installed but with only 2 of the 17 permissions the manifest declares. Go to **OAuth & Permissions → Reinstall to Workspace → Allow**. ⚠️ *Reinstalling issues a new bot token — any token you copied before this is useless (`slack_token_scopes_incomplete`).*
3. **Copy credentials** — the Bot User OAuth Token (OAuth & Permissions, *after* reinstalling) and the Signing Secret (Basic Information → App Credentials) — into `.env` under the exact names the envelope's `requiredEnvVars` lists (they're derived from your channel name: `INTELLIGENCE_CHANNEL_<NAME>_SLACK_BOT_TOKEN` / `..._SLACK_SIGNING_SECRET`). You do *not* need an `xapp-` app-level token — this app uses HTTP events, not Socket Mode.
4. **Re-run the resume command** from the envelope until `status: "completed"` and the adapter shows `attached`.
5. **Clean up:** once attached, the CLI reports `setup_credentials_removable` — the Slack credentials are now stored server-side and the `.env` copies can be deleted.

If you change the channel name, keep it in sync in three places: the `--name` flag, `CHANNEL_NAME` in `.env`, and the derived credential env-var names.

### 6. Run and validate

```bash
npm run dev
```

Wait for:

```
[main] channels online — {"cma-assistant":"online"}
```

Then validate from a **human** Slack account (don't send test messages as the bot):

1. `/invite @cma-assistant` to a channel, mention it with a question → useful reply, streamed into the thread
2. Unmentioned follow-up in that thread → reply
3. Unmentioned message in a fresh conversation → silence

Each new thread logs an Anthropic Console trace URL — open it to watch the agent's tool calls live.

## Customizing the agent

Everything about the agent's behavior lives in `cma/agent.yaml`: the model, the system prompt, and the toolset (`agent_toolset_20260401` = bash, file ops, glob/grep, web search/fetch in an Anthropic-hosted sandbox). Edit and apply with `ant beta:agents update` (step 2). New Slack threads pick up the new version; existing threads keep theirs. You can also add MCP servers, skills, or repo mounts — see the [Managed Agents docs](https://platform.claude.com/docs/en/managed-agents/overview).

## Project layout

| Path | Purpose |
|---|---|
| `cma/agent.yaml`, `cma/environment.yaml` | Version-controlled Managed Agent + environment definitions (applied via `ant`) |
| `src/cma.ts` | The bridge: session create/reuse, stream-first event drain, terminal-idle gate, timeout, stale-session recovery |
| `src/channel.ts` | `createChannel` + `onMention` / `onMessage` handlers |
| `src/agui-agent.ts` | AG-UI `AbstractAgent` adapter over the same bridge (the runtime requires a non-empty agent map) |
| `src/main.ts` | `CopilotRuntime` + Node listener + lifecycle |
| `scripts/smoke.ts` | Live end-to-end test of the bridge |
| `.copilotkit/channels.json` | Tracked, non-secret channel declaration |

## Troubleshooting

- **`slack_token_scopes_incomplete`** — you copied the bot token before "Reinstall to Workspace". Reinstall, copy the *new* token, re-run the resume command.
- **`hosted_gateway_ws_url_missing` warning** — benign on CopilotKit's hosted platform (the SDK's default gateway URL is used). Only set `COPILOTKIT_INTELLIGENCE_WS_URL` if you're pointed at a non-default deployment; without the right value `channels.ready()` hangs to its timeout instead of erroring.
- **Channel never reaches `online`** — run `npx copilotkit@latest channels status --json` and read `diagnostics`.
- **No hot-reload** — restart `npm run dev` after any handler/agent/channel change and re-verify `online`.
- **Managed vs. direct channels** — this project uses *managed* Intelligence Channels (`createChannel({ name })`, no adapters). Don't add a direct `@copilotkit/channels` Slack adapter on top; that's a separate integration path with its own transport.

## Notes & limits

- Inbound attachments are ignored (text-only prompts); the Managed Agents API accepts image/document blocks if you want to extend `src/cma.ts`.
- The thread→session map is a local JSON file; swap `src/session-store.ts` for a real store if you run more than one instance.
- Sessions accrue on the Anthropic side per Slack thread; archive old ones with `ant beta:sessions archive` if you want to tidy up.
